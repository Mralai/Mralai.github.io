# 03 · 杀毒误报规避与白名单指南（合法手段）

> 需求 4“规避 360/Windows Defender 等杀软误查杀、降低敏感进程特征、减少报毒”。
> 本工程采取的原则：**让程序呈现出“正规签名软件”应有的样子，而不是逃避检测**。
> 下列手段全部合规；本包不包含加壳、混淆、VM 保护、特征变异等对抗技术——
> 对内网正规软件它们既没必要，还会被引擎判定为恶意、加剧误报，且带来合规风险。

## 1. 为什么常规打包容易报毒（本方案已规避）

| 常规做法 | 杀软疑点 | 本方案 |
|---|---|---|
| PyInstaller 单文件 exe（内嵌解释器+自解压） | 解压释放子进程/内存执行特征，属启发式高发区 | ✅ 不用单文件打包；运行时就是官方 python.exe + 明文脚本 |
| 未签名自研 exe 从网上下载运行 | 未知发布者 + 无签名 | ✅ 内置 python.exe 带 **Python Software Foundation 官方签名**；引擎为透明自编译普通 exe（见 §4 可选公司签名） |
| 加壳/UPX/混淆 | 加壳程序 = 恶意行为前兆 | ✅ 完全没有 |
| 进程自我注入/驻留/自更新 | 木马行为 | ✅ 纯绿色目录运行；无注册表、无服务、无开机自启 |
| 自动联网下载/检查更新 | 远控/挖矿特征 | ✅ 代码层零外网（审计脚本 + 防火墙 + 文档三重验证） |
| 随机文件名/乱写进程名 | 伪装特征 | ✅ 固定规范进程名 llama-server.exe / pythonw.exe |

## 2. Windows Defender（Win10/11 目标机）

1. **部署侧一键加信任（管理员，推荐 IT 用）**：在“本地办公AI助手”目录执行
   ```powershell
   Add-MpPreference -ExclusionPath "D:\OfficeAgent"     # 路径按实际
   ```
   或 UI：Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加排除文件夹。
2. 误报申诉（更稳妥，让全网不再报）：[Microsoft 安全智能提交](https://www.microsoft.com/wdsi/filesubmission)
   提交 `engine\llama-server.exe` 与整个包，说明为内网办公工具（公开的 llama.cpp 项目
   + 本仓库描述），通常数日加入白名单。
3. 公司级：通过 Intune/GPO 下发排除项策略，避免每台手工操作。
4. SmartScreen 提示“已阻止未知发布者”：解除 zip 的 Mark-of-the-Web 后重新解压，
   或对 exe 做代码签名（见 §4）。

## 3. 360（360安全卫士/360杀毒，内网常见）

360 对“未知来源 exe + 无数字签名 + 释放子进程”组合最敏感。本包的降风险点同上表。
若仍出现误报（主要在首次运行或更新版本时）：

1. 弹窗选择“信任该程序 / 允许”；
2. 主动加白：360安全卫士 → 防护中心 → 信任与阻止 → 添加信任目录 `D:\OfficeAgent`；
   360杀毒 → 设置 → 白名单 → 添加文件/目录；
3. 误报申诉：[360误报提交](https://open.360.cn/)（需注册开发者账号）或客户端内
   “反馈误报”上传文件；说明公开来源（llama.cpp MIT / python.org 官方签名）即可；
4. 企业内网批量部署：建议先在一台机器验证通过、跑完申诉流程，再批量分发版本号一致
   的包（变更版本后重新验证一次）。

## 4. 进一步降低误报的可选手段

1. **代码签名证书（强烈推荐企业采购）**：购买 OV/EV 代码签名证书（如 Sectigo/GlobalSign，
   或国内 CA），对 `engine\llama-server.exe`、`llama-quantize.exe` 签名：
   ```powershell
   signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /f cert.pfx /p *** engine\llama-server.exe
   ```
   （签名过程需联网时间戳，属构建期操作，不影响运行时离线。）
   签名后 SmartScreen/Defender/360 对未知程序的红牌基本消失。签名后请勿改动 exe 内容，
   否则签名失效重新触发报毒。
2. 给引擎 exe 内嵌版本资源：本工程编译脚本已为 llama.cpp 生成标准 PE（带版本信息），
   无需额外处理；若自研组件请用 windres 写 .rc。
3. 分发通道：通过内网共享/邮件（不要从陌生网盘下载），减少 MOTW 带来的提示。
4. 版本一致性：杀软误报常与“新版本突然出现”有关，正式分发前先小范围试装。

## 5. 本工程承诺边界（明确不做的事）

- ❌ 不加壳、不混淆、不改进程名伪装、不注入其他进程；
- ❌ 不内置“检测到杀软就换行为”的逻辑（属对抗检测，非法）；
- ❌ 不利用系统漏洞/驱动白名单绕过；
- ✅ 透明可审计：全部源码随包交付（app\ 为明文 Python），杀软厂商可核验；
- ✅ 出问题时用正规流程解决：信任区/排除项/误报申诉。

## 6. 给 IT/审计部门的说明模板

> 本软件“本地办公AI助手”为公司内网公文写作辅助工具：
> 1) 内置官方签名的 Python 3.8 运行时与开源的 llama.cpp 推理引擎（MIT），模型为 Qwen2.5（Apache-2.0）；
> 2) 全离线运行：仅监听 127.0.0.1，无任何外网代码路径（可提供源码审计报告与防火墙规则）；
> 3) 绿色部署：无安装器、无注册表、无自启动、可整目录删除；
> 4) 数据不出机：处理对象仅限 kb_data 与上传文件，输出到 workspace。
> 请将其加入信任/白名单或协助完成误报申诉。
